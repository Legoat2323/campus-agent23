# 校园新生问答 Agent

一个面向大一新生的校园问答服务。问报到时间、快递点在哪、图书馆能借几本书这类问题，
它会从整理好的资料里找答案，找不到就说没有。

后端 FastAPI，知识库用 Chroma，模型是智谱 GLM-4-flash。

## 为什么做这个

新生入学前后问题特别碎：几点报到、从火车站怎么走、被子要不要带、学费怎么交。
这些信息散在学校官网、公众号、学长学姐的聊天记录里，哪个都不好找。

我自己刚经历完这一轮，把踩过的东西整理下来做成一个能问的机器人。
目标不是做一个比搜索引擎更强的东西，而是把"我们学校自己的经验"收拢到一个地方。

## 现在能做到什么

- 40 条问答，分成四个主题：报到前、报到当天、入学第一周、校园生活
- 网页界面，回答是流式输出的（一个字一个字出来），不是等半天弹一整段
- 能调天气工具（问"今天天气怎么样"会走 Function Calling）
- 记得上下文，能追问
- 不会瞎编：资料里没有就直说没有

我用 8 个问题测过（4 个主题各 2 条），检索和回答都是 8/8。
测试脚本在 `test_qa.py`，你可以自己跑。

## 数据从哪来

`data/` 下有 4 个 markdown 文件，一共 40 条。

**官方能查到的**（报到时间、学费、档案、户口）来自学校招生网的
[2026 年新生入学须知](https://www.guet.edu.cn/zs/2026/0728/c2214a158488/pagem.htm)，文件头写了来源。

**官方查不到的**（快递点分布、宿舍门禁时间、图书馆规则）是我自己整理的，
比如快递点分三处：前街是邮政，后街是中通申通和多多驿站，F 区篮球场旁边是顺丰京东极兔。

这类信息才是这个项目里真正有用的部分——网上搜不到，通用大模型也不知道。

有几条我确实不知道，标了"待确认"，没编。包括绿色通道的具体流程、宿舍分配规则、校园卡怎么办。
以后打听到了再补。

数据是 2026 级的，明年日期和电话可能要改。

## 怎么跑

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

新建 `.env`，写一行：

```
ZHIPU_API_KEY=你的key
```

然后建库、启动：

```powershell
.\.venv\Scripts\python.exe build_db.py
.\.venv\Scripts\python.exe main.py
```

打开 http://127.0.0.1:8000 就是界面，http://127.0.0.1:8000/docs 是接口文档。

> 注意别直接敲 `python`，要用 `.\.venv\Scripts\python.exe`。
> 系统的 Python 没装这些依赖，会报 ModuleNotFoundError。

## 目录

## 几个设计上的选择

### 按 `##` 切分，不用固定长度

一般做法是 `chunk_size=500` 按字数硬切。我一开始也这么写，结果一句话能被切两半，
检索出来是残缺的。

后来改成按 markdown 的 `##` 标题切：写数据时一条事实一段，切出来一条就是一块。
既不会被切碎，也不会把不相关的内容混在一起。

代价是数据必须写规范，标题乱了就切不对。

### 知识库按时间线分，不按部门分

学校的信息一般是按部门组织的：教务处管的、学工处管的、后勤管的。
但新生不会这么想，他只会想"我现在该干什么"。

所以四个文件是按报到进程排的：报到前、报到当天、第一周、之后的生活。

### 怎么控制模型瞎编

这是这个项目花时间最多的地方。

一开始问"学校附近有啥好吃的"，它编出了五家不存在的店，还自己写了一句
"以下推荐以虚构的学校为例"，然后接着编。

第一反应是改 prompt，加了几条规则：只依据资料回答、资料里没有就说没有、禁止编造店名。
**但没用。** 因为检索永远会返回 top-2，哪怕完全不相关，context 也不为空，
模型看到"食堂"两个字，就觉得这题能答，于是开始扩展。

后来改成用分数卡：`similarity_search_with_score` 会返回距离，越小越相关。
把距离超过阈值的片段直接丢掉，context 空了就返回一句固定的话。

阈值没拍脑袋定。我写了 `test_scores.py`，测 4 个库里有的问题（最差 0.87）
和 3 个库里没有的问题（最好 1.18），中间空档挺大，所以取 1.0。

改完再问"附近有啥好吃的"，它会说"这个问题我这边没有相关资料"。
问"快递点在哪"还是正常回答，没被误伤。

### 为什么没做重排和意图路由

我的招投标项目里做了查询重写、混合检索和 rerank，因为那边有 896 个切片、
用户说"价格"而文档写"投标报价权重"，不用这些根本召回不到。

这个项目只有 40 条，向量检索实测 100% 命中。这时候再加重排，只会上线延迟和多一个出错的地方。
等以后数据涨到 200 条以上再说。

## 踩过的坑

**测试脚本骗了我。** 第一次跑测试，检索显示 7/8，但回答是 8/8。
按理说检索没命中，模型不可能答对。查下来是我的关键词写的是"9月5"，
数据里是"9 月 5 日"，多了空格，字符串匹配失败。改成正则去掉空白就是 8/8。

这件事提醒我：指标异常的时候，先怀疑指标本身。

**改了代码没反应。** 改完 prompt 重启，发现没变化，最后发现是在另一个目录的
同名文件里改的。后来养成习惯，改完先看路径对不对。

**commit 信息乱码。** PowerShell 里提交中文信息，git 收到的编码不对，历史里是乱码。
现在 commit 信息统一用英文。

## 还没做的

- 三条"待确认"还没补，得去问学长
- 会话记忆存在内存里，重启就没了，应该换 Redis 或 SQLite
- 出错时返回 `{"error": ...}` 但 HTTP 状态码还是 200，应该用 HTTPException
- `print` 打的日志，应该换成 logging
- 没做鉴权、没限流、没配 CORS，只能本地跑
- `langchain_community` 里的 Chroma 已经废弃了，要迁移到 `langchain_chroma`
